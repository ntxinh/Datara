# Secrets

Passwords are stored only in the system Secret Service (GNOME Keyring,
KeePassXC, …; visible in Seahorse) via the `secret-service` crate on the
D-Bus session bus (`crates/secrets`). Items are tagged with
`{"application": "io.github.ntxinh.Datara", "secret-reference": <ref>}` so
they stay manageable outside the app.

A `ConnectionProfile` carries a `SecretReference` like `mssql/7/password`
generated by `ConnectionRepo` on insert; SQLite and TOML store the
reference, never the secret. A serialized profile has no `password` key
(unit test: `connection_profile_json_carries_reference_not_secret`).
At connect time `DatabaseService` resolves the reference into a
`secrecy::SecretString`, so `Debug`, `Display`, and `Serialize` cannot
leak it — `Credentials` has a manual `Debug` impl printing `password:
"***"` (test: `credentials_debug_redacts_password`). Secret material
never reaches logs or error messages; `tracing` calls carry no
credential fields.

The local SQLite file holds profile metadata and is pinned to mode
`0600` by `Storage::open` (test: `db_file_is_owner_only`). Deleting a
connection removes both the profile row and its Secret Service item.
